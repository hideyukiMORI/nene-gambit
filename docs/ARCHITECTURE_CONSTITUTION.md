# アーキテクチャ憲章 — NeNe Gambit

> Status: normative（規範）/ 2026-10-25 初版
> 判断の根拠は [ADR 0001](adr/0001-strictness-is-mechanically-enforced.md)。
> 本書が沈黙している領域は [CODING_RULES.md](CODING_RULES.md) と公式の Swift 6 標準に従う。

## 0. この文書の読み方

**すべての規則は「機械強制」の状態を持つ。**

| 表記 | 意味 |
| --- | --- |
| **active** | 違反すると `make check` が落ちる。人の記憶に依存しない |
| **planned** | 規範だが、まだ機械が見ていない。**この行に触れる変更は PR で明示的に自己レビューすること** |
| **不能** | 言語・道具の仕様上、機械では塞げない。塞げないことを明記して残す |
| **不採用** | 検討して採らなかった。理由を必ず併記する（再提案は同じ理由への反論から始める） |

🔴 **planned を active と書き換えないこと。** 未実装の強制を実装済みに見せるのは、
規約全体の信頼を壊す唯一の行為である。実装してから書き換える。
どの規則がいまどの状態かの正本は [QUALITY_GATES.md](QUALITY_GATES.md) の強制マトリクスであり、
文書整合検査（CNF-006）が「本書に定義があるのにマトリクスに行が無い」「本書の状態とマトリクスの状態が違う」を拒否する。

### 強制の実体は 5 層ある

| 層 | 実体 | 守るもの |
| --- | --- | --- |
| コンパイラ | Swift 6 言語モード・strict concurrency・網羅性・`treatAllWarnings(as: .error)`・`ExistentialAny` | **不正な状態を「書けなく」する** |
| ビルドのモジュールグラフ | SwiftPM の target（`Package.swift`）と正本 `docs/architecture/module-graph.txt` | 層の依存方向 |
| 整形 | `swift-format lint --strict`（設定は `.swift-format` 1 つ） | 文字列としての正本 |
| 静的解析 | SwiftLint 0.65.1（`.swiftlint.yml` の `only_rules` で 1 つずつ名指し） | 書けてしまうが書くべきでないこと・複雑度 |
| 規約検査 | `eng/conformance.py`（Python 3 標準ライブラリだけ） | **NeNe Gambit として守るべきこと**。Swift に API 単位の禁止の道具が無いので、その層もここが字句で担う |

道具が重なっても責務は重ねない。同じ規則を 2 か所で設定すると、片方を緩めても誰も気づかなくなる。

### Swift がどこまで届いたか

先行事例（NENE-PIXEL＝Kotlin / nene-recall＝Go / xi-tools＝Rust / NeNeCommander＝C# / NeNeClock＝Java）が到達した点との比較。
本リポジトリの列は 2026-10-25 の Swift 6.4.1 の実測（[phase0-results.json](quality/phase0-results.json)・ADR 0001）による。

| 規則 | Kotlin | Go | Rust | C# | Java | **Swift 6.4.1（本リポジトリの実測）** |
| --- | --- | --- | --- | --- | --- | --- |
| 不正状態を表現不能に・網羅性 | ある | 無い | ある | ある | ある | 不十分。ケース漏れは error。`default` / `case _` / `case let x` は診断なし。既知ケースを漏らす `@unknown default` は warning で exit 0 |
| 公開状態は不変 | ある | 無い | ある | ある | ほぼある | 不十分。`let` / `private(set)` は拒む。`public var` とクラス参照の中身は通る |
| `null` の意味は一つ | 不十分 | 不十分 | ある | ある | 不十分 | 不十分。暗黙のゼロ値は無い。IUO と強制アンラップは通る |
| 非公開コンストラクタ＋唯一のファクトリ | ある | 不十分 | ある | ある | ある | 不十分。`private init` は守られる。同一モジュールの memberwise・`unsafeBitCast`・`Decodable` の合成 init が迂回する |
| 決定性（時刻・乱数・環境を読ませない） | planned | planned | ある | ある | ある | 言語では無い。時計・乱数・`CommandLine` は標準ライブラリだけで読める |
| 依存方向は物理的 | ある | ある | ある | ある | ある | ある（target 間）。標準モジュールは漏れる |
| 抑制は例外であって道具ではない | waiver 台帳 | 理由必須 | forbid 層 | 全面禁止 | waiver 台帳 | 不十分。`@diagnose(..., as: ignored)`・manifest の `treatWarning`・lint の ignore が理由なしで効く。waiver 台帳 |

🔴 **穴が残ることを書かずに厳格さを主張しない。** 塞げなかったものはここと第 1 節に「不能」として残す。

## 1. 憲章規則

### ARC-001 — 一つの意味に一つの正典経路

一つの意味には、正典となる型・所有者・振る舞いの経路が **ちょうど 1 つ**存在する。
並行するサービス、同義の別モデル、アダプタ固有の業務ロジック、同じ概念の別名を作らない。
置き換えが必要なら、呼び出し側の移行と旧経路の削除を**同じ変更で**行う。段階移行が要るときは期限付きの waiver に書く。

NeNe Gambit での具体: 合法手の生成・指し手の適用・終局の判定は Core にそれぞれ 1 経路。指し手の内部表記は 1 つで、
表示用の変換は Render だけが持つ。盤の表現（0x88・mailbox・bitboard 等）は 1 つに決めて ADR に書き、混ぜない。

- 機械強制: **planned**（レビュー事項。「意味が同じか」は機械が判定できない）
- 補助: CNF-001（総称名の禁止）が「役割の分からない第 2 経路」の温床を減らす

### ARC-002 — 依存方向は物理的である

依存は [PROJECT_LAYOUT.md](PROJECT_LAYOUT.md) のグラフに従う。禁じた依存は「レビューで気をつけること」ではなく
**import できないこと**でなければならない。循環は許さない。

SwiftPM は宣言していない target の import を `no such module` で、宣言の循環を `cyclic dependency declaration found` で拒む
（実測 M6-a〜M6-d）。その宣言そのものを、正本 `docs/architecture/module-graph.txt` と規約検査（CNF-010）が突き合わせる。

- 機械強制: **active** → SwiftPM の target グラフ＋CNF-010

### ARC-003 — 中核はプラットフォームから独立している

Core・Engine・Render は、端末・ファイル・ネットワーク・現在時刻・既定ロケール・既定タイムゾーン・環境を知らない。
プラットフォームは**型のある値か引数**から入る。

🔑 Swift の標準モジュール（Foundation・Glibc・Dispatch）は、依存を宣言しなくても import できてしまう（実測 M5-a・M5-b・M5-g）。
ビルドグラフでは塞げないので、target ごとの import 許可リスト（CNF-011）が塞ぐ。Core・Engine・Render の許可リストは空である。

- 機械強制: **active** → CNF-011（import 許可リスト）＋CNF-012（標準ライブラリだけで読める時計・乱数・プロセス状態）

### ARC-004 — 状態には唯一の所有者がいる

| 状態 | 意味 | 所有者 | 変更経路 |
| --- | --- | --- | --- |
| 局面 | 盤上の駒・手番・キャスリング権・アンパッサンの升・手数 | Core の `Position`（値） | `Position.applying(_:)` だけ |
| 1 局の履歴 | 指した手・各手の前の局面・同一局面の判定の鍵 | Core の `Game`（値） | `Game.playing(_:)` だけ。終局の判定は `Game.status` だけ |
| 対局の列 | いまの局・何局目か・通算の勝敗・白黒の指し手の種類 | Engine の `GameSeries`（値）を合成ルートの `Screensaver` が 1 つ持つ | `GameSeries.advanced(using:)` だけ |
| 乱数の状態 | シード付き PRNG（`SplitMix64`）の内部状態 | 合成ルートの `Screensaver` | `advanced(using: &generator)` に `inout` で渡す |
| 駒の字形の選択 | 英字か駒記号か | 合成ルートの `Screensaver` | 起動オプションと `g` のキー |
| 画面の前フレーム | 差分描画の比較元のセル格子 | 合成ルートの `Screensaver`（`previous`） | 描くたびに入れ替える。大きさが変わったら捨てる |
| 端末の元の設定 | termios の退避値 | Terminal の `ConsoleState`（1 か所） | `Console.open` と `restoreTerminal` だけ |
| 届いたシグナル | 終了の要求・大きさの変化 | Terminal の原子的な旗 | ハンドラが立て、`Console.takeSignals` が取り出す |

同じ事実を 2 つの区分に独立して持たない。派生値は再計算するか、無効化を明示したキャッシュにする。

- 機械強制: **planned**

### ARC-005 — 可変性は隔離区画にのみ存在する

外から見える Core・Engine・Render の状態は不変とする（値型＋純粋関数）。可変な状態を持ってよいのは次の区画だけである。

| 区画 | 何が可変か | なぜ必要か |
| --- | --- | --- |
| Terminal | termios の退避値・届いたシグナルの旗 | 異常終了のシグナルハンドラからも端末を戻せるようにする（ADR 0006） |
| 合成ルート（`nene-gambit` の `Screensaver`） | 対局の列・乱数の状態・駒の字形の選択・前フレーム | 時計で 1 歩ずつ進めるループの持ち主。前フレームは差分描画の比較元 |
| 関数の内側のローカル変数 | 探索中の作業用の値 | 外へ漏れない。指し手の適用と戻しを探索の中で行うため |

隔離区画は、可変なコレクション・配列・ビルダを外へ返さず、検証済みの値型だけを受け取る。

🔴 **区画を増やさない。** 必要になったら、この表と ADR を先に変える。

- 機械強制: **planned**（補助: CNF-016 が公開の格納 `var` と `open` を拒否する）

### ARC-006 — 合成は明示的である

依存は合成ルート（`nene-gambit`）で与える。サービスロケータ・リフレクションによる発見・暗黙のシングルトン・
可変なグローバル登録簿を使わない。DI フレームワークを入れるには ADR が要る。

合成ルートは**プロセスそのものの責務**も持つ。標準入出力への直書きとプロセスの終了コードを扱ってよいのは合成ルートだけである。
出してよいのは**起動できなかった理由 1 行**と、`--version` の 1 行だけで、ログの手段として使わない。画面の描画は Terminal が `write(2)` で行う。

- 機械強制: **planned**（補助: CNF-017 が合成ルート以外の `print` / `readLine` / `exit` 等を拒否し、CNF-014 がリフレクションを拒否する。暗黙のシングルトンはレビュー事項）

### ARC-007 — 既定で決定的である

Core・Engine・Render・Terminal は、現在時刻・乱数・既定ロケール・既定タイムゾーン・環境変数・プロセス状態を**直接読まない**。
これらは引数から入る。読んでよいのは **合成ルート `nene-gambit` ただ 1 区画**であり、
そのことは「レビューの約束」ではなく、依存グラフの正本の `role=composition-root` という宣言の差分として残す。

探索は時間ではなく深さ（またはノード数）で打ち切る。乱数はシード付きの自前 PRNG で、**同じシード＝同じ対局の列**。

- 機械強制: **active** → CNF-012（合成ルート以外で `SystemRandomNumberGenerator`・`ContinuousClock`・`CommandLine`・`getenv`・`using:` の無い `random(...)` 等を拒否）＋CNF-011
- 補足: テストソースにも同じ禁止を適用する。**テストが実時刻を読むことも決定性の破壊である。**

### ARC-008 — 境界は一度だけ検証する

外から来た値（起動オプション・FEN の文字列・キー入力）は、最初の自前の境界で検証し、その場で Core の型へ変換する。
検証前の生の値を中核へ流さない。

- 機械強制: **planned**（レビュー事項）
- 補助: SWF-007（唯一のファクトリ）が、検証を通らない値の生成を難しくする

### ARC-009 — 永続化の契約は版を持つ

NeNe Gambit は永続化を持たない（設定ファイル・保存棋譜は施主の要件に無い）。持つ必要が生じたら、保存形式に明示的な版を持たせ、
読めない版は既定値へ黙って落とさず型のある失敗として返す、という規則をその ADR で具体化する。

- 機械強制: **planned**（補助: CNF-015 が `Codable` を拒否するので、永続化の型は ADR 無しには書けない）

### ARC-010 — 期待される結果は型で表す

期待される失敗（FEN が読めない・合法でない指し手）と終局の理由は、閉じた enum で返す。
例外はプログラム上の欠陥に限り、それは `precondition` / `fatalError` で表す。`nil`・boolean・文字列で複数の業務的な結果を表さない。

- 機械強制: **planned**（補助: CNF-019 が製品コードの `throw` / `try` / `catch` を拒否する。`nil` や boolean で結果を表すことはレビュー事項）

### ARC-011 — UI は状態を描き、意図を発行する

Render は局面と HUD の値から文字セルの格子という**値**を作るだけで、端末を知らない。Terminal は格子を差分で書き、
キー入力を閉じた enum の意図に変えて渡すだけで、対局の進め方を知らない。整形の判断は Render、状態遷移は合成ルートと Core に置く。

- 機械強制: **planned**（Render が端末に触れないことは CNF-011 の import 許可リストが補助する）

### ARC-012 — アーキテクチャは利便性に優先する

道具の近道・ライブラリの便利機能・最適化が、状態の所有者・モジュールグラフ・契約の境界を迂回することを許さない。
アーキテクチャが間違っているなら ADR で明示的に変える。ユーティリティを装った局所的な例外を作らない。

- 機械強制: **不能**（判断そのものが対象。QLT-010 の手続きで担保する）

## 2. 強制を置く順番

規則は、確実に効く**いちばん早い層**に置く。

1. 言語の型・可視性・網羅性
2. ビルドシステムのモジュールグラフ
3. コンパイラの設定（警告はエラー・`ExistentialAny`）
4. API 単位の禁止（Swift には専用の道具が無いので規約検査の字句検査が担う）
5. 静的解析（SwiftLint）
6. 規約検査（`eng/conformance.py`）
7. CI のマージゲート
8. まだ自動化できない判断だけをレビューへ

レビューだけの強制は一時的な状態であり、[QUALITY_GATES.md](QUALITY_GATES.md) に `planned` として残す。
