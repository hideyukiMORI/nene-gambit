# ADR 0013 — 駒記号のポーンは輪郭の ♙（U+2659）にする。♟ は絵文字の字形で描かれ色が効かない

- 状態: 受理（ADR 0005 の決定 3「駒記号は U+265A〜U+265F の塗りつぶしの字形」のうち、ポーンを置き換える）
- 日付: 2026-10-25
- Issue: #24
- 影響する規則: ARC-011 / FR-07

## 文脈

README 用に Windows Terminal（WSL2）の実機の画面を写したところ（2026-10-25）、駒記号のとき白と黒のポーンがどちらも紫の絵文字で描かれ、見分けが付かなかった。
ほかの駒は前景色どおりだった。

- U+265F（BLACK CHESS PAWN）だけが Unicode の Emoji=Yes。U+265A〜U+265E と U+2654〜U+2659 は Emoji=No
- 端末のフォントに駒記号が無く、代わりのフォント（色付きの絵文字のフォント）が U+265F を絵文字の字形で描く。絵文字の字形には前景色が効かない
- 異体字セレクタ U+FE0E（テキスト表示）を付けた `U+265F U+FE0E` も実機で試したが、同じく紫の絵文字で描かれた
- 同じ画面で U+2659（WHITE CHESS PAWN・輪郭）は前景色どおりに描かれた

## 決定

1. 駒記号のポーンは、白も黒も U+2659（輪郭の字形）にする。キングからナイトは U+265A〜U+265E（塗りつぶし）のまま。白と黒は従来どおり色で分ける
2. 駒記号に絵文字の性質（Unicode の Emoji）を持つ文字を使わない

## 強制

- 単体テスト（`symbolsAvoidEmojiCodePoints`）: 駒記号で描いた初期局面の盤に 6 種類の字形があり、どれも `isEmoji` でないこと。U+265F に戻すと落ちることを確かめた
- 2 桁の扱い（ADR 0010・0011）は U+2654〜U+265F の範囲で判定しているので、U+2659 にもそのまま効く。カーソルを 1 進める端末・2 進める端末の再生テストも U+2659 で通る

## 結果

- 実機で、白のポーンは白、黒のポーンはテーマの黒の色で描かれ、ほかの駒と同じく色で見分けられる
- 失うもの: ポーンだけ輪郭の字形になり、塗りつぶしの駒と線の太さがそろわない。ポーンは小さく見える

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| U+265F の後に U+FE0E を付ける | 実機の Windows Terminal で効かなかった（紫の絵文字のまま） |
| 6 種類すべてを輪郭の字形（U+2654〜U+2659）にする | 実機で写して比べると線が細く、盤の上で駒が軽く見える（ADR 0005 で塗りつぶしを選んだ理由と同じ） |
| ポーンだけ別の記号（`●` など）にする | 駒記号の組の中で 1 つだけチェスの字形でなくなる |
