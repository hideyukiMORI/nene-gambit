# ADR 0003 — 盤は 64 升の値型の配列、指し手は「元・先・昇格先」の 1 表記、適用は新しい局面を返す

- 状態: 受理
- 日付: 2026-10-25
- Issue: #3
- 影響する規則: ARC-001 / ARC-004 / ARC-005 / SWF-001 / SWF-004 / SWF-007

## 文脈

指示書は「盤の表現（0x88・mailbox・bitboard 等）は 1 つに決めて ADR に書く。表現を混ぜない」「指し手の表記は内部で 1 つ」を求めている。
NeNe Gambit に要るのは強さではなく「見ていて飽きない対局」で、探索の深さは浅い（性格の中身は施主の未決 Q7）。
一方で perft は深さ 5 まで公表値と一致させる（FR-02）。Kiwipete の深さ 5 は 193,690,690 局面ある。

Swift 6.4 の標準ライブラリには固定長で値型の `InlineArray<N, Element>` があり、Linux でも使えることを確かめた（Issue #3）。

## 決定

1. **盤は `InlineArray<64, Piece?>` の 1 つだけ**（`Board`）。升は `index = rank * 8 + file`（a1 = 0、h8 = 63）。
   方向は（筋の差, 段の差）で表し、盤の外へ出たかは `Square.at(file:rank:)` が nil を返すことで判る（0x88 や番兵の升は使わない）
2. **指し手は `Move(from, to, promotion)` の 1 表記**（UCI 形式と同じ情報）。キャスリングは「王が 2 筋動く手」、
   アンパッサンは「ポーンがアンパッサンの升へ斜めに動く手」として表し、種別のフラグは持たずに局面から導く。
   `Move` の init は internal で、Core の外の指し手は `Position.legalMoves()` からしか得られない。SAN 等の表示用の表記は Render が持つ
3. **指し手の適用は新しい局面を返す**（copy-make）。`Position.applying(_:)` は元の局面を変えない。
   指示書の不変条件「指し手を適用して戻すと局面が完全に元に戻る」は、**元の値を持っていること**で成り立たせ、
   テストは「全合法手を適用した後も元の局面と FEN が変わらない」ことを確かめる（`PositionTests.applyingLeavesTheOriginalUntouched`）
4. 合法手は「駒の動き方の上で指せる手」を作り、適用した局面で自分の王が利きの中にある手を捨てて得る。キャスリングの通過升と
   「王手中はキャスリングできない」は生成の側で見る
5. 局面のハッシュ（同一局面 3 回の判定に使う）は、履歴を扱う Phase 3 の手順 2 で足す。いまは `Position` の `Hashable`（全欄の値の比較）だけ

## 強制

- **planned**（ARC-001）: 盤の表現と指し手の表記を混ぜないことは、型が 1 つしか無いことで成り立つが、2 つ目を作らないことはレビュー事項
- 補助（active）: `Move` の init が internal なので、Core の外で指し手を作れない（コンパイラ・M4-b と同じ仕組み）

## 結果

- perft は release 構成で 6 局面すべての深さ 5 が約 34 秒（ADR 0004）。速さの点で bitboard を選ぶ理由は今のところ無い
- 局面は値なので、Engine の探索は局面をそのまま引数に渡せる。可変な盤を探索の中で戻す処理（unmake）が要らない
- 失うもの: 1 手ごとに 64 升の配列を複製する。make/unmake 型より遅い。探索が遅すぎたら、測ってから ADR で判断する
- 正直に記録しておくこと: `applying` に合法でない手を渡したときの検査は「動かす駒が無ければ止める」だけで、それ以外の不正な手は
  検出しない（`legalMoves()` 以外から `Move` を得る経路が無いので、Core の外からは渡せない）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| bitboard | 速いが、ビット演算の表と魔法数が要り、読む側の負担が大きい。いまの用途（浅い探索＋perft 深さ 5）には速さが要らない |
| 0x88 / 10×12 の番兵つき mailbox | 盤の外の判定が速いが、`Square` の index と盤の配列の添字が別の番号になり、変換の経路が 2 つになる |
| `[Piece?]`（ヒープの配列） | 1 手ごとにヒープの確保が要る。`InlineArray` なら値の複製で済む |
| 指し手に種別（キャスリング・アンパッサン・昇格）のフラグを持たせる | 同じ情報を局面と指し手の 2 か所に持つことになる（ARC-004） |
| make / unmake（可変な盤を戻す） | 中核に可変な区画を増やすことになる（ARC-005）。値型の copy-make で perft の速さが足りた |
