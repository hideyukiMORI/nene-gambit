# ADR 0008 — Windows Terminal では 24 ビット色、256 色は最近傍、駒記号の幅は端末に測らせる

- 状態: 受理（決定 3 は ADR 0010 で置き換えた。Windows Terminal は駒記号の幅を 1 と答えて約 2 桁で描くので、問い合わせでは見分けられなかった）
- 日付: 2026-10-25
- Issue: #9
- 影響する規則: ARC-007 / ARC-011 / FR-07 / FR-11

## 文脈

施主が Phase 3 の手順 3 で Windows Terminal を見た（2026-10-25）。罫線の枠は出ていた（ADR 0007 の幅の判定が働いた）。
「駒記号が少し右寄り」「1 手 0.7 秒は少し早い」と指摘があった。スクリーンショットの盤は AMBER テーマの暗い升が黄土色と暗い赤
（#5f5f00 / #5f0000 相当）で描かれていて、24 ビットではなく 256 色に丸められていた。

- WSL の中では `COLORTERM` が設定されていないことが多い。Windows Terminal は `WT_SESSION` を必ず設定する
- これまでの 256 色の近似は 6×6×6 の立方体の各成分を丸めるだけで、立方体の 0 の次の段は 95 なので、暗い色が明るい色へ飛ぶ
- 駒記号（U+265A〜U+265F）は East Asian Ambiguous で、端末が 2 桁で描くと、3 桁の升の中央の桁から 2 桁を使って半桁右に寄り、
  右の括弧が駒の右半分に重なる

## 決定

1. 合成ルートは `WT_SESSION` があるか、`COLORTERM` が truecolor / 24bit なら 24 ビットの色を使う（環境を読むのは合成ルートだけ・ARC-007）
2. 256 色は、色立方体（16〜231）と灰色の 24 段（232〜255）から RGB の距離がいちばん近い番号を選ぶ（`Palette256`）
3. 起動時に `♚` を書いてカーソル位置を問い合わせ、2 桁進んだら駒記号を 2 桁の文字として扱う（`TerminalTraits.wideSymbols`）。
   格子では右隣のセルを「右半分」（`Cell.isWideTail`）にし、差分描画はそこに何も書かない。大きな盤では右の括弧を 1 桁右へずらし、
   縮小版（1 升 3 桁）では括弧が升に収まらないので描かない。奇数桁の升に 2 桁の文字は真ん中に置けないので、半桁右に寄るのは残る
4. 枠・駒記号の幅・色の方式は「端末の性質」として `TerminalTraits` にまとめ、`DisplayOptions` は字形とテーマと性質の 3 つにする
5. 1 手の間隔の既定を 1.0 秒にする（FR-11。`--move-interval` で変えられる）

## 強制

- 12 テーマの地の色が 256 色の近似で暗いまま保たれること、2 桁の駒記号の右半分に差分描画が何も書かないこと（書いたバイト列を「2 桁の文字はカーソルを 2 進める」
  端末として再生して確かめる）は単体テスト。後者は、右半分を読み飛ばす処理を外すとテストが落ちることを確かめた
- **planned**: Windows Terminal での実際の見え方は施主が見る（QLT-013）

## 結果

- Windows Terminal では、施主がデザインで見た色そのものになる
- 🔴 駒記号を 2 桁で描く端末では、駒が升の中央から半桁右に寄るのは直らない（奇数桁の升の限界）。気になるなら英字（既定）を使う

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 256 色のままにして利用者に `COLORTERM=truecolor` を設定してもらう | 施主の環境（FR-09 の Windows Terminal）で既定の見た目が崩れる |
| 升を偶数桁（8 桁）にして 2 桁の駒記号を中央に置く | 盤が 64 桁になって 100 桁の端末で HUD が入らない。英字では逆に半桁ずれる |
| 駒記号が 2 桁の端末では駒記号を使わせない | 施主の決定（FR-07: 駒記号はオプション）を狭める |
