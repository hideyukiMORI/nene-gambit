# ADR 0010 — 駒記号は常に 2 桁ぶんの字形として扱い、駒記号のときは升を偶数桁にする

- 状態: 受理（ADR 0008 の決定 3「駒記号の幅を端末に問い合わせる」を置き換える。決定 1 の「右隣のセルに何も書かない」は ADR 0011 で置き換えた）
- 日付: 2026-10-25
- Issue: #13
- 影響する規則: ARC-001 / ARC-011 / FR-07

## 文脈

ADR 0008 の後も、施主の Windows Terminal で駒記号が升の中央からずれて見えた（2026-10-25・2 回目）。スクリーンショット（縮小版の盤）を測ると:

- Windows Terminal は駒記号（U+265A〜U+265F）でカーソルを 1 桁進める（幅の問い合わせは 1 を返し、空の升の `[ ]` は 2 つとも出ていた）
- しかし字形は約 2 桁の幅で描かれる。端末のフォント（Cascadia）に駒記号が無く、代わりのフォントの字形が広い。直前の手の升では、駒の右の `]` が駒に隠れていた
- 2 桁ぶんの字形は、奇数桁の升（3 桁・7 桁）の中央には置けない

つまり「端末が答える幅」と「描かれる幅」が違い、問い合わせでは見分けられない。

## 決定

1. 駒記号は、端末の答えに関係なく「描くと 2 桁を使う字形」として扱う。右隣のセルは `isWideTail`（何も書かない）にする。幅の問い合わせはやめる
2. 駒記号のときは升を偶数桁にする: 大きな盤は 6 桁（英字は 7 桁）、縮小版は 4 桁（英字は 3 桁）。字形は升の中央の 2 桁、直前の手の括弧はその両隣で、升の中に収まる
3. 縮小版で駒記号を使うと盤が 8 桁広くなるので、HUD を盤の右に寄せる。縮小版に要る大きさは英字 67×15・駒記号 75×15。足りなければ必要な大きさを文言で示す
4. 差分描画は、2 桁ぶんの字形を書いた後のカーソルの位置を当てにしない（端末が 1 進めても 2 進めても合うように、次に書くセルで必ずカーソルを動かす）

## 強制

- 駒記号の字形が偶数桁の升の中央 2 桁に来て、括弧が升に収まること（大きな盤と縮小版）、縮小版の駒記号に 75 桁が要ることは単体テスト
- 書いたバイト列を「駒記号でカーソルを 1 進める端末」と「2 進める端末」の両方として再生し、どのセルも格子どおりに書かれ、右半分には何も書かれないことを
  単体テストで確かめる。ADR 0008 のカーソルの扱い（2 進めると決めつける）に戻すと、「1 進める端末」の場合だけ落ちることを確かめた

## 結果

- 英字は奇数桁の升の中央の 1 桁、駒記号は偶数桁の升の中央の 2 桁で、どちらも左右の余白が揃う
- 駒記号の切り替え（`g`）で盤の幅が変わる（大きな盤 56 ⇔ 48 桁・縮小版 24 ⇔ 32 桁）。HUD の位置は大きな盤では変わらず、縮小版では右へ動く
- 🔴 駒記号を本当に 1 桁で描く端末（フォントに細い駒記号がある端末）では、字形が中央の 2 桁の左側に寄る。施主の環境（FR-09）に合わせた

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 幅の問い合わせを続ける | Windows Terminal は 1 と答えて 2 桁ぶんで描くので、問い合わせでは見分けられない |
| 升の桁数を英字でも偶数にする | 英字（1 桁）が奇数桁の升なら中央に置けるのに、半桁ずれる |
| 駒記号を使える端末を利用者に選ばせる（起動オプションで幅を指定） | 利用者が知らなくてよいことを聞くことになる |
