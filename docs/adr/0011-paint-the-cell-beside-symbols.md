# ADR 0011 — 駒記号の右隣のセルは升の色の空白として書く

- 状態: 受理（ADR 0010 の決定 1「右隣のセルには何も書かない」を置き換える。偶数桁の升と中央 2 桁の配置は 0010 のまま）
- 日付: 2026-10-25
- Issue: #15
- 影響する規則: ARC-001 / ARC-011 / FR-07

## 文脈

ADR 0010 の後、施主の Windows Terminal（2026-10-25・3 回目）では、駒記号の右に暗い縦の帯が出て、駒が左に寄って見えた。
スクリーンショットを測ると、駒の位置は偶数桁の升のほぼ中央で、狙いどおりだった。帯は、右隣のセルに何も書かなかったために、画面を消したときの端末の既定の背景が
升の色で塗られずに残ったもの。施主の見立ても「背景色があってればいいのかな」だった。

Windows Terminal は、後から書いたセルの上にも駒記号の字形を描く（2 回目のスクリーンショットで、駒の右の `]` が駒に隠れていた）。

## 決定

1. 駒記号の右隣のセルは、升を塗ったときの空白（升の背景の色）のまま書く。2 桁の文字を表すセルの種類（`Cell.isWideTail`・`Grid.writeWide`）は消す
2. 差分描画は、駒記号（U+2654〜U+265F）を書いた後のカーソルの位置を当てにせず、次に書くセルで必ずカーソルを動かす。
   端末が 1 進めても 2 進めても、右隣の空白は右隣のセルに書かれる

## 強制

- 右隣のセルが升の背景の空白であること（単体テスト）
- 書いたバイト列を「駒記号で 1 進める端末」「2 進める端末」として再生し、すべてのセルが格子どおりの桁に書かれること（単体テスト）。
  カーソルを当てにしない処理を外すと「2 進める端末」の場合だけ落ちることを確かめた

## 結果

- 升の背景が駒の右まで揃う。駒は偶数桁の升の中央に来る
- 🔴 駒記号を本当に 2 桁で描いてカーソルも 2 進める端末では、右隣の空白が字形の右半分の上に書かれ、字形の右半分が消える可能性がある。施主の環境（FR-09）に合わせた

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 奇数桁の升に戻して右寄りを許す | 施主は許容も考えたが、測ると問題は位置ではなく背景だった |
| 画面を消すときに升の色で塗る | 消すのは画面全体で、升ごとの色を知らない。差分描画の外に第 2 の塗り方を作ることになる |
